# T016 SPU/SKU

以 V2.2 第 5、23–26、28–31、61–64、68 节为依据。迁移 0014_product_import_batch 依赖 0013_product_master 和原分类基线。品牌和计量单位使用独立公司目录。SPU 保存品族、品牌和分类，SKU 保存规格值、MPN、单位、税率、追踪模式和购销属性。字段沿用冻结命名，编码按 NFKC、去首尾空白、大写后在公司内唯一。非空 MPN 在公司与品牌内唯一。

SKU 创建要求已审核的 SPU。分类校验复用 T015 的归属及祖先状态，选择可用叶子分类。创建时物化分类配置的默认单位、税率和跟踪模式，现有 SKU 保留当时的值。实际属性使用后端计算的有效 Schema。供应链、库存数量、库存实例和正式迁移不属于本任务。

## 模式变更

允许 quantity、serial、batch、non_stock。普通编辑不接受 tracking_mode。申请和批准分开，批准权限与申请权限分开。批准时锁定 SKU，检查版本、申请有效性、T101 职责分离及交易事实 Provider 后更新模式。审计保留前后模式、申请与批准人员及关联申请 ID，原因保存在关联申请记录。无库存或交易表的阶段用测试 Provider 覆盖已交易拒绝。

未来正式过账先锁 SKU，再确认跟踪模式，最后写持久事实，始终在同一事务内。审批服务使用相同 SKU 锁，并通过 Provider 验证已过账出入库及退货、调整、转移、SN/批次流转和确认期初。零余额不解除历史锁定。

## 导入与映射

标准商品模板和预检支持 Excel 和 UTF-8 CSV。预检执行正常校验，回滚目录数据，仅记录预检审计。成功预检冻结原文件及标准化计划，数据库触发器保护快照。提交后由独立审核人批准或填写原因驳回。发布仅接受获批批次，重新核对分类链、有效 Schema、品牌、单位、SPU 版本与唯一约束。先生成并审核新 SPU，再创建 SKU，任一失败整批回滚并记录 FAILED。旧商品映射保持来源编号，允许多个来源指向同一 SKU。导入候选或低置信度项只进入人工审核状态。

开发与测试 Seed 使用合成品牌、单位、14 个 SPU 和 14 个 SKU，覆盖四种模式。遇到现存产品、审批、映射或分类默认值时，迁移拒绝有损降级。
