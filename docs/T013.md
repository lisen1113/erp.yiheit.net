# T013 客户主数据

依据 V2.2 第23–25、28–31、89、109节。客户管理入口为 `/customers`，围绕统一往来单位扩展客户角色。

## 数据边界

`0009_customer_profile` 新增 `customer_profile`。字段为 `id`、`company_id`、`business_partner_id`、`customer_no`、`customer_type`、`salesperson_id`、`delivery_address`、`is_active`、`is_synthetic`、`is_deleted`、`created_at/by`、`updated_at/by`、`version_no`。同公司外键保证客户档案、主体及销售人员归属一致。同公司主体最多一个客户档案。客户编号先做 NFKC、去首尾空白并转大写，由数据库公司内唯一约束保护。

往来主体继续保存全称、简称、信用额度（CNY，numeric(18,2)）、默认账期、发票税号、开票抬头及地址电话、结算银行与账号、默认联系人及备注。客户页面复用 `payment_terms_days`、`tax_no` 和 `invoice_address_phone`，维持现有含义及字段授权。收货地址和客户启停状态由客户档案独立保存。

新建主体与客户档案使用同一事务和幂等回执。现有供应商挂接客户档案时，主体角色变成 BOTH，原 UUID 保留。客户停用只写客户档案和审计，原因使用受控分类。现有停用销售人员的关联可以查询。更新共享字段时同时核对客户版本与主体版本。

## 验收接口

`/api/v1/customers` 支持列表、查询、新建、更新、详情及独立启停。`/customers/salespeople` 下拉数据只返回范围内有效员工。SELF 使用销售人员归属，部门范围沿用拒绝行为。银行账号默认脱敏，完整详情须显式申请并满足既有独立权限和 MFA。审计记录银行账号已变更的事实以及信用额度前后 Decimal 金额。

未来交易调用 `assert_customer_available_for_new_transaction()`，在写交易的同一事务内检查客户及主体是否有效。停用客户仍可查询详情，默认列表排除不可用客户。

Seed 使用 T010/T012 同源的十个合成客户档案，涵盖普通、信用、预付、停用及双角色主体。历史多编码映射可复用现有主体与档案 UUID；导入模板与流程的范围见 T013-01。
